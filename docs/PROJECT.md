# Municipal Incident Platform — цели и назначение проекта

## Краткое описание

**Municipal Incident Platform** — единая цифровая система для муниципального управления территорией: выявление, учёт, приоритизация и контроль устранения проблем на уровне района. Платформа объединяет веб-центр диспетчеризации (дашборд, карта, реестр инцидентов), мобильный канал для полевых сотрудников и граждан, а также координацию между ответственными организациями (коммунальные службы, исполнители, аналитики).

Пилотная география реализации — **район Nərimanov (Баку)** с привязкой к границам района, геозонам и открытым пространственным данным об объектах инфраструктуры.

---

## Какую задачу решает проект

В городской среде десятки типов нарушений и аварийных ситуаций возникают одновременно: от косметического износа фасадов до срывов коммунальных сетей и последствий непогоды. Без единой системы:

- проблемы фиксируются разрозненно (звонки, бумага, мессенджеры);
- нет единой «картины района» для руководства;
- сложно назначить ответственного, срок и проконтролировать исполнение;
- координация между Azersu, Azeriqaz, Azerishiq, благоустройством и др. затруднена;
- невозможно объективно оценить SLA, просрочки и эффективность работ.

Проект закрывает этот разрыв: **каждая зафиксированная проблема становится геопривязанным инцидентом** с категорией, приоритетом, исполнителем, сроком, историей изменений и местом на живой карте района.

## Цели проекта (в соответствии с исходными требованиями)

### 1. Механизм выявления, учёта, приоритизации и мониторинга решения

| Требование | Реализация в платформе |
|------------|------------------------|
| Систематический, плановый и маршрутизированный обход территории | Регистрация инцидентов диспетчером или полевым инспектором; тип `INSPECTION`; привязка к геозонам для зональной ответственности |
| Оперативная регистрация детальной информации | Форма инцидента: заголовок, описание, категория/подкатегория, координаты, адрес, вложения (фото/документы), приоритет |
| Надзор и направление со стороны ответственных лиц | RBAC/ABAC: роли диспетчера, регионального админа, аналитика, оператора коммунальной организации; назначение исполнителя и организации |
| Доступность через мобильное приложение (фото + геолокация + категория) | Expo-приложение: съёмка/выбор медиа, GPS и выбор точки на карте, категория и приоритет, отправка через API `/api/problems` |
| Живая «карта ситуации» района | Интерактивная карта (2D/3D): маркеры, кластеризация, тепловая карта, слои по типам проблем, граница Nərimanov, объекты района |
| Интерактивная отчётность — Dashboard | KPI (открытые, просроченные, SLA %), графики по статусам/категориям/приоритетам, «горячие» зоны, лента событий, drill-down |
| Цифровой архив и аудит | Статус `ARCHIVED`, отдельная архивная карта; журнал `audit_log` и timeline `incident_history` (кто, когда, что изменил) |
| Определение приоритетов | Уровни `LOW` / `MEDIUM` / `HIGH` / `CRITICAL`; влияние на SLA и отображение на дашборде |
| Назначение исполнителя и ответственного, deadline, статус до полного решения | Поля `assignedTo`, `organization`, `deadline`, `slaDueAt`; статусы `NEW` → `IN_PROGRESS` → `PENDING` → `RESOLVED`; планировщик задач исполнителя с учётом доступности |
| Автоматическое предупреждение при просрочке deadline | Планировщик SLA (каждые 10 мин): перевод в `OVERDUE`, push через WebSocket и сервис уведомлений |
| Координация коммунальных организаций с учётом ЧС и погоды | Категории utilities и `weather_emergency`; привязка к организациям (`azersu`, `azeriqaz`, `azerishiq`); отдельные права оператора организации |

### 2. Классы проблем, которые система должна охватывать

Ниже — соответствие перечня из ТЗ и **категорий в системе** (`backend/prisma/seed-data/categories.ts`):

| Проблема по ТЗ | Категория в системе |
|----------------|---------------------|
| Фасады: выцветание, отслоение материала | `facades` (İnfrastruktur) |
| Увядание/гибель озеленения, несвоевременная стрижка | `dry_zones`, `mowing` (Yaşıllaşdırma) |
| Последствия падения деревьев | `tree_fall` |
| Последствия подтоплений | `floods` (Hava və fövqəladə) |
| Обледенение тротуаров и улиц | `ice` |
| Проблемы чистоты улиц и тротуаров | `street_dirt` |
| Состояние мусорных контейнеров | `overflow_bins` |
| Невосстановленный асфальт после прокладки коммуникаций | `comm_lines`, `asphalt_repair` |
| Износ дорожного покрытия | `road_surface` |
| Рекламные конструкции | `billboards` |
| Витрины торговых объектов | `storefronts` |
| Детские/спортивные площадки, скамейки | `playgrounds`, `benches` |
| Фонтаны | `fountains` |
| Состояние тротуарного покрытия и бордюров | `sidewalks`, `curbs` |
| Ограждения строительных площадок | `fences` |
| Освещение: столбы и освещённые зоны | `broken_lamps`, `dark_areas` |
| Аварии и перебои воды, газа, электричества | `water`, `gas`, `electricity` |
| Штормовые повреждения | `storm_damage` |

Дополнительно платформа поддерживает **гражданские обращения** (`IncidentReport`, действие `CITIZEN_REPORT` в истории) — несколько заявок могут быть сгруппированы в один инцидент при совпадении категории и локации.

## Целевые пользователи

| Роль | Назначение |
|------|------------|
| Super Admin / Regional Admin | Полный доступ, геозоны, исполнители, аудит |
| Dispatcher | Создание и маршрутизация инцидентов, назначение задач |
| Field Worker (Executor) | Работа с назначенными инцидентами на карте и в списке |
| Analyst | Аналитика и экспорт без изменения операционных данных |
| Utility Operator | Инциденты только своей организации (газ, вода, свет) |
| Citizen / Mobile user | Регистрация проблем с телефона |
| Viewer | Только просмотр дашборда, карты и реестра |

Доступ ограничивается **разрешениями** (view_dashboard, view_map, assign_task, view_audit и др.) и **областью видимости** (весь район, геозона, назначенные задачи, организация).

## Ключевые возможности платформы

### Веб-центр диспетчеризации

- **Dashboard** — оперативная сводка: открытые и просроченные задачи, SLA, распределение по категориям и статусам, топ геозон, индекс «здоровья» территории.
- **Карта** — режимы 2D/3D, фильтры по слоям (вода, газ, дороги, освещение, санитария, погодные ЧС и др.), кластеры и heatmap.
- **Реестр инцидентов** — таблица с фильтрами, массовые действия, детальный drawer: timeline, вложения, SLA, гражданские обращения.
- **Исполнители** — справочник ответственных по категориям; календарь доступности; планирование слотов задач с учётом занятости.
- **Realtime** — обновления карты и списков через Socket.IO без перезагрузки страницы.

### Мобильное приложение

- Регистрация проблемы с **фотографией/видео**, **геолокацией** и **категорией**.
- Просмотр своих обращений, уведомлений и новостей района.
- Совместимость с backend через REST API `/api/*`.

### Надёжность данных и контроль

- **История инцидента** — каждое изменение статуса, приоритета, срока, назначения.
- **Аудит** — действия пользователей в системе (создание, редактирование, назначение).
- **Архив** — закрытые инциденты на отдельной карте для долгосрочного хранения.
- **PostGIS** — пространственные запросы (радиус, пересечения) для аналитики «горячих» точек.

### Координация и SLA

- Автоматический расчёт `slaDueAt` при создании инцидента.
- Периодическая проверка просрочек и статус `OVERDUE`.
- Уведомления ответственным при нарушении срока.

### Искусственный интеллект (вспомогательно)

- API для подсказок по описанию проблемы и анализу фото (Groq), ответы по умолчанию на азербайджанском языке — ускорение заполнения мобильной формы и карточки инцидента.

## Ожидаемый эффект для муниципалитета

1. **Прозрачность** — руководство видит актуальную карту и метрики, а не разрозненные отчёты.
2. **Скорость реакции** — от фиксации на месте до назначения исполнителя в одной системе.
3. **Подотчётность** — сроки, просрочки и история изменений зафиксированы цифрово.
4. **Межведомственная координация** — коммунальные организации работают в общем реестре с разграничением доступа.
5. **Планирование** — аналитика по категориям и геозонам поддерживает превентивные и оперативные мероприятия, в том числе в периоды неблагоприятной погоды (категории `weather_emergency`).

## Границы и направления развития

Уже реализовано в рамках hackathon/MVP: полный цикл инцидента, карта Nərimanov, дашборд, мобильная подача заявок, SLA-просрочки, аудит, исполнители с календарём доступности, интеграция организаций.

Потенциальное развитие по исходному ТЗ (не обязательно входит в текущую версию):

- Прямая интеграция с **прогнозом погоды** (в т.ч. OpenWeather) для превентивных планов.
- Формализованные **маршруты обхода** с чек-листами и GPS-трекингом бригад.
- Расширение на другие районы Баку по той же модели геоданных.

## Локальная разработка

1. Скопировать переменные: `cp .env.example .env` (в корне репозитория).
2. Поднять инфраструктуру: `docker compose up -d postgres redis`.
3. **Первичная настройка БД** (один раз на новой машине или после новых миграций):

```bash
cd backend && npx prisma migrate dev && npm run prisma:seed
```

Команда создаёт схему в PostgreSQL/PostGIS и заполняет демо-данные (роли, категории, геозоны, тестовые инциденты).

4. Запуск всего стека из корня: `npm run start:all` (backend + frontend + mobile + Docker). Только веб: `npm run dev`.

Подробности, порты и демо-аккаунты — в [README.md](../README.md).
